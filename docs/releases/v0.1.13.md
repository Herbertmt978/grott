# Grott 0.1.13

This release includes the reviewed PR13/14 grottserver fixes, maintained through
PR16/17, plus PR15's container security updates and license packaging. The GitHub
Releases page is the supported-availability authority: use the published images
only when their matching release entry exists. The release process publishes
matching runtime and add-on artifacts for all four supported architectures.

## Datalogger keepalive

**What was the problem?** Standalone grottserver connections could linger after
a datalogger silently disappeared, leaving stale connections behind.

**What did we do?** Enable TCP keepalive on accepted sockets. On Linux the idle
time is 120 seconds, probe interval 30 seconds and probe count three. Unsupported
options are skipped; an optional socket-setting failure does not reject a client.

**Why was it a problem?** Silent network loss need not produce an immediate EOF.

**Benefit to users:** The operating system can detect dead standalone-server
connections. This is not an MQTT heartbeat or a change to proxy packet decoding.

## Connection cleanup and rapid reconnection

**What was the problem?** Looking up a disconnected socket's peer could fail
before its queue, logger registration and descriptor were cleaned up. A quick
reconnection from the same address and port could also lose its replacement queue.

**What did we do?** Cache the peer returned by accept, use the server's own queue
registry, tolerate repeated cleanup and always close the socket. Retire an old
same-peer connection before registering its replacement.

**Why was it a problem?** Stale state could accumulate or prevent a reconnected
datalogger from receiving acknowledgements and commands.

**Benefit to users:** Disconnects and resets are covered by regression tests,
including late events from a retired socket. Packaged-process tests exercise
protocol 02/05/06 acknowledgements, HTTP registration and repeated FIN/RST cycles.

## Container security and permission

**What was the problem?** The pinned Alpine crypto and UUID packages needed
security updates, and the container artifacts needed their license included.

**What did we do?** Update libcrypto/libssl3 to 3.5.8-r0 and libuuid to 2.42.3-r1,
and package LICENSE.md in both containers. The Grott Personal Use License covers
personal, non-commercial use. On 2026-09-07 the owner confirmed Johan Meijer's
authorization to publish it; upstream redistribution permission has been obtained.

**Why was it a problem?** Image users need both maintained dependencies and the
terms governing the inherited code. This permission does not authorize commercial use or reuse unless Johan Meijer separately agrees;
any financial reward or appreciation is directed to him. A donation alone does not grant commercial rights.

**Benefit to users:** Both images include the license at /app/LICENSE.md and
receive vulnerability, secret and final-artifact checks. Historical immutable
releases retain their recorded terms and are not rewritten.

## Layout and Home Assistant behavior carried forward

**What was the problem?** Packaged example layouts once changed built-in
decoding, including displaying SPH battery SOC 64 as 0.64. Entity-map changes
could also create unwanted Home Assistant discovery and statistics changes.

**What did we do?** Retain the reviewed three-file allowlist and final-image validator
from v0.1.12. The v0_1_9_standard profile retains 32 entities for
supported generic/MOD records. An omitted option selects that profile;
retained discovery cleanup begins on the next live packet. Broad MOD discovery stays opt-in.

**Why was it a problem?** A socket maintenance release must not silently change
sensor interpretation or the normal Home Assistant entity set.

**Benefit to users:** These merges do not change the parser, record layouts,
discovery defaults or proxy forwarding implementation. SPH, MIN, TL3, T060120
and other unavailable hardware families remain fixture/container tested,
not real-hardware tested. Earlier MOD hardware evidence is historical, not a
substitute for this candidate's required UAT.

## Changes carried forward from v0.1.11-beta

**What was the problem?** Users upgrading from older releases need to understand
the cumulative behavior, not just these socket fixes.

**What did we do?** Retain TCP frame reassembly, partial-write handling,
forwarding before optional processing, CRC publication guards, contained Influx
failures, JSON plus safe literal configuration parsing and XML compatibility.
Non-root containers, read-only support, passive health checks and exact-source annotated tags
also remain. The earlier v0.1.12 stable promotion preserved its
beta's runtime and layout behavior; v0.1.13 adds the changes described above.

**Why was it a problem?** Calling this another unchanged beta promotion would
hide the new container dependencies and grottserver behavior.

**Benefit to users:** The upgrade scope is explicit. PR12's offline HA/MQTT
feature, battery scheduling controls and encrypted ShineWiFi-X session decoding
are not included. The packaged Docker profiles support proxy mode only. For an
existing server or sniff installation, do not upgrade either packaged image as
a supported migration; standalone source users must retain their own configuration.

## Upgrade validation and rollback

**What was the problem?** A successful image build cannot prove live telemetry,
cloud freshness or Home Assistant registry safety.

**What did we do?** Require exact-source CI, both images' local validation,
four-platform builds, security scans and controlled live UAT under RELEASING.md.
The owner approved a 15-minute live-feed observation with verified backups and
restoration of the previous version afterward. July's historical observation
waiver does not apply to this release. UAT must check advancing grott_last_push,
plausible values, ShinePhone freshness, restart recovery and Home Assistant Repairs.

**Why was it a problem?** Image rollback does not restore Home Assistant
registry/configuration, retained MQTT discovery or statistics metadata.

**Benefit to users:** The verified full **Grott pre-update rollback** backup,
including retained MQTT coverage, is required before UAT. Docker rollback pins
the previous immutable runtime and restores configuration. Home Assistant
rollback restores that named backup; a previous add-on digest alone is not a
historical-install mechanism. The previous stable v0.1.12 artifacts are:

- Runtime: ghcr.io/herbertmt978/grott@sha256:40765fbd328056e39dd0d7752253fd94091551808290995f695ef2fa3753c7a3
- Add-on: ghcr.io/herbertmt978/grott-ha-docker@sha256:904a58273d06e6279e22524a58a8749c26eb0bb320a19a66cb7e43f4948b1327

No release gate or protection is waived. The Home Assistant add-on remains
experimental; stable is the release channel, not universal hardware qualification.
